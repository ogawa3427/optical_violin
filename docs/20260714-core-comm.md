# migration ファームのコア分担とコア間通信

> 日付: 2026-07-14 / 関連: `src/main.cpp`, `src/io/telemetry.{h,cpp}`, `src/infer/causal.h`

設計原則: **Core 0 は Core 1 を絶対に待たせない**（telemetry.h 冒頭に明記）。

## コア分担

### Core 1 — Arduino メインループ（演奏パス、レイテンシ最優先）

- `loop()`: Serial2(G5) HID パケット解析 → 弓パルス毎 `CausalEngine::push()` → 即 expr 確定 →
  Serial1(G1/G2) へ CC#11 送出。**パルス受信→MIDI 送出が 1 本の同期チェーン**で、
  間に他コアもキュー待ちも挟まない（実測 45µs/パルス @k中位、0713 計測）
- `tick()`（Δ比無音タイムアウト）+ 300ms 無音 flush（保険）
- 15ms スロットルの乗っ取り入力: `M5.update()`+BtnA / joystick(Wire0) / fader(ADC)。
  `g_eng.i_ext/pct_ext` へ直接書く（同一コア内なので排他不要）
- レイテンシ計測（`ESP.getCycleCount()` → ns 換算は Core1 側で実施）

### Core 0 — `m62_telemetry` タスク（優先度 1 = 低、`xTaskCreatePinnedToCore(..., 0)`）

- 単一キューを空になるまで吸い上げ → 統計更新（pulse/note カウント、end reason d/t、iA ヒスト）
- USB CDC へ CSV 送出（`Serial.availableForWrite() >= n` の時だけ書く = PC が読んでなくても非ブロック）
- LCD 描画 100ms 周期（M5Canvas 128×128 → pushSprite）、ループは `vTaskDelay(10ms)`

## コア間通信（3 経路、すべて 1→0 の単方向）

| 経路 | 中身 | 同期方式 |
|---|---|---|
| FreeRTOS キュー（256 要素） | `TelemetryRecord`＝kind 'P'（PulseRecord: 計測値）/ 'N'（NoteRecord: 境界）の union | `xQueueSend(timeout=0)` ノンブロッキング。満杯なら**捨てて** `s_pulse_drops++`（LCD に `dr` 表示） |
| `Telemetry::setStatus()` | mode / i_ext / pct_ext（乗っ取りタグ・iA マーカー・p バー用） | `volatile` 変数への単純代入 |
| drops カウンタ | キューあふれ数 | `volatile uint32_t` |

- **P/N を単一キューに混載する理由**: 発生順の保存。別キューだと Core 0 の吸い上げ順で
  NoteOff が次ノートのパルスより後に CSV へ出て PC 側ノート集計が壊れる（実測済み）
- setStatus が mutex 無し volatile で済む理由: 32bit 書き込み単発で、表示用途なので
  多少のティアリング/1フレーム遅延に実害がない

## ハードウェア資源割り付け

| 資源 | 用途 |
|---|---|
| UART0 (USB CDC) | PC デバッグ + テレメトリ CSV |
| UART1 = G1/G2 | Unit Synth MIDI (31250) |
| UART2 = G5/G6 | HID 入力 (115200、TX 実質未使用) |
| I2C **NUM_0** (`Wire`) = G39(SDA)/G38(SCL) | Joystick Unit 0x52 |
| I2C **NUM_1** | **M5Unified が内蔵 IMU 用に占有**（sda=45 scl=0）。`Wire1` は使用禁止 |
| ADC1_CH6 = G7 | Unit Fader アナログ |
| SPI (M5GFX 管理) | LCD GC9107 |
